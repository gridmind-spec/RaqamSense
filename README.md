# بصمة رقم | RaqamSense

مشروع **تعلّم آلة تطبيقي** يصنّف الأرقام المكتوبة بخط اليد من الصور، ويعرض نتيجة شجرة القرار بصورة تفاعلية من واجهة عربية `RTL` تدعم المظهرين الفاتح والداكن. يتبع مراحل الورشة: تجهيز البيانات، التعلم الخاضع، تقييم النموذج، ضبط المعاملات، Gradio، Hugging Face، وGitHub. وهو **تطبيق مستقل ضمن المهارات المدرّسة**، وليس إعادة تنفيذ مثال درجات الطلاب الخاص بالمدربة. ملف `WORKSHOP_ALIGNMENT.md` يبيّن المطابقة والتفاوت بدقة.

## 1. المشكلة — ماذا يتوقّع مشروعنا؟

كيف نعلّم الحاسوب معرفة الرقم المكتوب باليد؟ بدل بناء قاعدة يدوية لكل شكل رقم، ندرّب نموذج تصنيف على صور مرقمة ثم نختبره على صور لم يتدرّب عليها. الفائدة تعليمية: إظهار دورة تطوير نموذج ML قابل للتفسير وكيف تؤثر معالجة الصورة في النتيجة. ليس بديلًا عن أنظمة OCR الإنتاجية.

## 2. البيانات — المصدر والتنظيف

- المصدر: [scikit-learn Digits](https://scikit-learn.org/stable/modules/generated/sklearn.datasets.load_digits.html)، مجموعة معروفة تضم **1,797 صورة رمادية بحجم 8×8**؛ الهدف من 0 إلى 9.
- الخصائص: 64 قيمة بكسل من 0 إلى 16. توليد جدول `cleaned_data.csv` بأسماء `pixel_00` إلى `pixel_63` وعمود `digit`.
- التنظيف: فحص المفقود والمكرر وأنواع القيم والمدى، وإزالة التكرار المطابق إن وجد، ثم فحص نهائي. لا نعوّض بيانات مفقودة عالميًا قبل التقسيم لتجنّب التسريب؛ مصدر البيانات لم يحوِ قيمًا مفقودة.
- نتيجة التنظيف محفوظة في `reports/cleaning_report.json` ويمكن إعادة إنتاجها بملف `train_model.py`.
- **هندسة الخصائص:** تحويل الصورة إلى 64 قيمة عددية وتوحيدها عند الإدخال الجديد إلى المدى `0–16`. في هذا المشروع نحتفظ بالخصائص الأساسية ولا نخترع خصائص غير مجربة.

## 3. النموذج — نوعه وإعداداته

**`DecisionTreeClassifier`** من scikit-learn. فصلنا مجموعة الاختبار المستقلة 20% عن التطوير 80%. ثم قسّمنا التطوير إلى تدريب وتحقق، وتجربنا عمق الشجرة `3, 5, 7, 9, 12, None`، وثبتنا `min_samples_leaf=2` و`random_state=42`. اخترنا العمق حسب **Validation accuracy**، ثم أعدنا التدريب على كل مجموعة التطوير، وقيمنا الأداء على الاختبار النهائي.

الميزة: خوارزمية مشروحة في الورشة ويمكن تفسير قراراتها؛ القيد: أداء محدود على أشكال خارج بيانات التدريب، مقارنة بنماذج صور أكثر تعقيدًا.

## 4. النتائج — أرقام اختبار حقيقية

| المؤشر | النتيجة |
|---|---:|
| عدد صور التدريب أثناء الضبط | 1,077 |
| عدد صور التحقق | 360 |
| عدد صور الاختبار النهائي | 360 |
| أفضل عمق للشجرة | 9 |
| Accuracy على الاختبار النهائي | **83.06%** |
| خط أساس الفئة الأكثر تكرارًا | ~10% |

> هذه النتائج مولّدة بواسطة `python train_model.py` مع `random_state=42` ونسخة scikit-learn الموثّقة في `reports/metrics.json`. قد تختلف قليلًا مع إصدارات مختلفة. ليست نسبة ضمان على صور الهاتف والرسم الحر، ولا «ثقة» احتمالية معايرة.

ملفات الأدلة: `reports/metrics.json`، `reports/confusion_matrix.csv`، `reports/hyperparameter_search.csv`، `reports/test_predictions.csv`.

## 5. واجهة التطبيق — Gradio وHugging Face

**شغّل محليًا:**

```bash
python -m pip install -r requirements.txt
python train_model.py
python app.py
```

ثم افتح `http://127.0.0.1:7860`، جرّب الصور من المجموعة المستقلة، أو ارفع صورة رقم واضح، أو ارسم على لوحة التحدّي.

**النشر على Hugging Face Spaces:**

1. افتح [Hugging Face Spaces](https://huggingface.co/new-space)، وأنشئ Space بنوع **Gradio**، واختر `Public` إذا كان مطلوبًا من لجنة التقييم.
2. ارفع **محتويات هذا المجلد** إلى جذر Space (`app.py`, `train_model.py`, `requirements.txt`, `README.md`, `cleaned_data.csv`, `model/`, `reports/`, `app_assets/`).
3. انتظر ظهور حالة **Running** في صفحة Space، وجرب صورة من الأمثلة. نسخ مكتبات التشغيل مذكورة في `requirements.txt`. إذا تعارضت بيئة `joblib`، يعيد البرنامج التدريب تلقائيًا من البيانات الأصلية بنفس الإعدادات.
4. انسخ رابط Space النهائي وشاركه مع اللجنة. **لم يُنشأ أو يُتحقق من رابط نشر ضمن هذه الحزمة؛ يحتاج حساب المشارك.**

**GitHub:** أنشئ مستودعًا وارفع الملفات نفسها. ارفع `README.md` بأقسامه الستة، وتأكد من أن `cleaned_data.csv` وملفات الأدلة موجودة. لا ترفع توكنات حساباتك.

## تجربة العرض أمام الحكام

1. اشرح المشكلة: تعرّف الرقم المكتوب بخط اليد من الصورة.
2. اذكر المصدر الحقيقي، شكل المصفوفة 8×8، التنظيف وغياب التسريب.
3. اشرح فصل Validation عن Test ولماذا اخترنا العمق 9؛ اعرض Accuracy الموثّقة لا المتوقعة.
4. افتح مثال `0` ثم مثال `8` وشغّل النموذج، ثم جرّب الرسم الحر واذكر أن الاختلاف عن بيانات التدريب قد يسبب أخطاء.
5. أجب عن «لماذا لم تحصل على 100%؟» بتوضيح قيود Decision Tree ومحدودية التعميم.
